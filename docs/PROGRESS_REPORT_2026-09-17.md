# 可视分析探索推荐项目阶段汇报

- 汇报日期：2026 年 9 月 17 日
- 项目仓库：[azccjl/SCV](https://github.com/azccjl/SCV)
- 当前原型：本地 Streamlit 应用 `http://127.0.0.1:8501`

## 一、这一阶段在解决什么问题

我目前希望研究的问题是：

> 可视分析系统能否根据分析者当前的探索状态，给出少量“下一步值得探索”的候选方向，并通过可视化解释推荐原因，让分析者保留最终判断权？

这里的重点不是穷举整个分析空间，也不是让 AI 直接给出一个所谓的最优答案，而是从一个规模可控的 **one-step-ahead exploration** 开始：系统根据当前的变量、模式、情景、时间、空间范围和分析方法生成少量候选，对候选的信息价值、目标相关性、证据稳定性和计算成本进行排序，再让分析者选择、验证或回退。

这一思路对应导师强调的三个核心部分：

- **Data：** 系统正在处理什么数据，数据覆盖和不确定性如何；
- **Task：** 用户要定位变化、比较情景，还是验证一个科学假设；
- **Human perception / interaction：** 推荐如何被理解、采用、拒绝和修正。

## 二、最近已经完成的工作

### 2.1 完成第三组数据的初步任务分析

我选择 SciVis Contest 2026 第三组 NEX-GDDP-CMIP6 数据作为当前原型的数据基础。该数据具有多模式、多情景、日尺度和空间网格等特征，适合用来测试“在大分析空间中推荐下一步”的想法。

目前把任务初步拆成四个阶段：

1. **识别变化：** 查看单个模式、情景和年份中的时间与空间结构；
2. **解释差异：** 比较历史、SSP2-4.5、SSP5-8.5，以及不同气候模式的差异；
3. **验证稳健性：** 检查数据覆盖、模式一致性和参数敏感性；
4. **下一步推荐：** 给出少量候选操作，解释排序依据，并允许采用和回退。

### 2.2 搭建了可运行的可视分析原型

当前系统已经实现：

- 自动扫描本地 NetCDF 文件，并建立“模式 - 情景 - 年份 - 变量”数据目录；
- 选择气候模式、情景、年份和主要变量；
- 展示月平均时间序列和年度平均空间热图；
- 明确区分季节内变化、跨年份变化和相对历史基准的距平；
- 比较多个模式和情景，展示跨模式中位数、四分位范围及同向模式比例；
- 显示有效格点比例和缺测警告，避免把空白区域解释为零变化；
- 导出当前比较结果；
- 保存探索历史，支持采用推荐和回退上一步；
- 在页面侧栏显示批量数据下载进度，并支持刷新数据目录。

温度已经统一转换为摄氏度，降水统一转换为 mm/day，避免不同源文件单位不一致导致误读。

### 2.3 建立了可续传的数据下载流程

我没有直接下载约 28 TB 的完整数据，而是采用“下载年度源文件 - 裁剪研究区域 - 校验 - 保留小切片”的方式控制空间占用。

目前已完成一组锚点数据：

| 内容 | 当前规模 |
| --- | ---: |
| 气候模式 | 3 个：MRI-ESM2-0、GFDL-ESM4、MIROC6 |
| 情景 | historical、SSP2-4.5、SSP5-8.5 |
| 锚点年份 | historical 2010；两个未来情景 2035 |
| 变量 | `tas`、`pr` |
| 区域年度切片 | 9 个 |
| 裁剪后本地体积 | 约 14.4 MiB |

下载脚本支持 HTTP Range 断点续传、失败重试、单任务超时和状态账本。完整的第二阶段计划为 225 个区域年度切片，但现在没有直接启动全量任务，避免在科学问题尚未收敛时堆积数据。

## 三、从现有材料中获得的启发

### 3.1 从 KuroshioVis 报告获得的启发

这篇报告最值得借鉴的不是具体的黑潮可视化形式，而是它组织科学分析的方式：

1. **用显式假设组织探索。** 用户先提出待检验关系，系统再决定所需事件、变量和统计证据，而不是让用户在很多图中漫无目的浏览。
2. **从个例转向集合证据。** 单个事件的信号容易被噪声覆盖，需要跨事件对齐和积累证据。迁移到气候投影中，就是不能只看单模式、单年份，而应查看跨模式方向一致性和离散范围。
3. **摘要必须能下钻。** Evidence Matrix 用一个单元格概括关系，但悬停后仍能查看事件级散点、回归线、置信区间和详细统计量。系统不能只给颜色或一句 AI 结论。
4. **AI 应围绕底层数据组织结论。** AI 可以拆解假设和整理证据，但不应绕过数据计算直接“看图说话”。

这让我意识到，当前系统下一步最需要的不是增加更多普通图表，而是建立“假设 - 摘要证据 - 原始数据 - 验证动作”的完整链条。

### 3.2 从《大模型赋能的可视化与可视分析研究综述》获得的启发

综述把可视分析描述为从“人操作参数化工具”逐渐转向“人 - Agent - 知识协同”。对本项目最有价值的启发有三点：

- 将自然语言科学目标翻译成 **可见、可编辑的分析状态**，而不是直接生成不可检查的代码或结论；
- 让 Agent 参与任务分解、候选生成和结果组织，但数值计算仍由确定性分析模块完成；
- 评价不能只看模型回答是否流畅，还要看用户是否更好地完成任务、理解不确定性并发现错误。

因此，后续即使接入大模型，也会先定义结构化的证据包，包括当前假设、筛选条件、计算指标、数据覆盖、模式一致性、不确定性说明和数据来源。AI 只能基于这些字段生成解释。

### 3.3 从三篇相关论文方向获得的启发

#### Guided Exploration of Iterative Schedule Modifications

对我的启发是：面对巨大、无法完全自动优化的决策空间，可以让系统生成局部修改候选，让专家逐步判断。迁移到本项目中，就是推荐“换变量、换模式、换情景、换年份、换区域或换统计方法”，而不是声称找到了全局最优分析路径。

#### Juicy Interactive Visualization

对我的启发是：交互不只是为了缩短完成时间，也会影响用户是否愿意继续探索。后续评价应加入持续探索意愿、主动检查反例的次数、回退和分支行为等指标。不过反馈设计需要克制，不能用动画或奖励效果掩盖科学不确定性。

#### ConceptViz

我最想迁移的是 `Identification -> Interpretation -> Validation` 流程。目前系统的四个页面已经是这一结构的初步实现。后续可以把 AI 的角色限定为：帮助识别候选、解释结构化证据、提出验证动作，而不是直接宣布科学结论。

### 3.4 从个人想法和导师建议中进一步明确的方向

导师建议让我意识到，研究贡献不能只落在推荐算法本身，而要回答推荐怎样帮助人高效、可信地完成任务。因此我目前倾向把贡献表述为：

> 透明的一步推荐能否减少专家的盲目尝试，并帮助其形成可追溯、包含不确定性、能够被反复验证的证据链？

## 四、下一阶段决定做什么

### 4.1 第一优先级：可下钻证据矩阵

计划把“模式 × 情景”或“模式 × 年份”组织成矩阵：

- 单元格颜色表示相对历史基准的变化方向和幅度；
- 描边或透明度表示数据覆盖与证据稳定性；
- 悬停显示具体数值、单位、样本量和缺测率；
- 点击后联动到日尺度时间序列和空间网格；
- 对模式分歧和证据不足的单元格给出明显提示。

这一功能可以直接复用现有数据汇总结果，也是当前最能强化“变化差异是否明显”的可视化。

### 4.2 第二优先级：假设工作区

在侧栏加入“研究假设”，并将其转成用户可以确认和修改的字段：

```text
变量 + 比较对象 + 时间范围 + 空间范围 + 预期方向 + 验证条件
```

例如，把“2035 年 SSP5-8.5 下温度相对历史升高，并且多数模式方向一致”转换成明确的变量、情景和证据门槛。所有图表和推荐都围绕这份状态更新。

### 4.3 第三优先级：真正的验证闭环

目前“验证稳健性”主要还是清单和数据覆盖提示。下一步计划加入：

- 可调整历史基准期；
- 季节和空间范围敏感性对比；
- 替换或排除单个模式后的结果变化；
- 验证前后结论对照；
- 只有完成替代设置检查后，才允许把结论标记为“已验证的工作假设”。

### 4.4 第四优先级：证据绑定的 AI 助手

先用规则模板生成“支持证据、反例或不足、下一项验证动作”，建立可追溯机制；之后再连接大模型。这样能够先验证交互逻辑和研究价值，避免把项目过早变成一个普通聊天界面。

### 4.5 数据扩展

数据扩展将以科学问题为依据，而不是追求文件体积：

1. 先扩展历史期和未来期的连续年份，支持真正的长期变化分析；
2. 再加入 `tasmax`、`tasmin` 和 `hurs`，探索热日、暖夜和湿热复合风险；
3. 如果最终更强调黑潮或中尺度海气耦合，再接入对应海洋数据，而不是用 NEX-GDDP 强行解释海洋动力过程。

## 五、当前遇到的问题

### 5.1 科学问题还需要进一步收敛

当前原型能够展示数据和推荐候选，但最终研究任务仍有两种可能：

- 继续以第三组气候投影数据研究跨模式、跨情景探索；
- 转向更贴近导师团队的黑潮或海气耦合任务，研究框架迁移。

两者的数据结构和专家任务不同，需要尽早确定主场景，否则后续容易同时做两套系统而缺少一个清晰贡献。

### 5.2 现有数据只能验证界面，不能支持长期科学结论

目前只有 2010 和 2035 两个锚点年份、3 个模式。它们足够验证数据管线、跨模式比较和交互，但不能被表述为稳定的长期趋势。需要扩展连续年份、确定合理历史基准期，并考虑季节和极端指标。

### 5.3 “值得探索”的定义仍是启发式的

当前候选排序主要考虑目标相关性、信息增益、创新性、证据稳定性和计算成本，但权重仍是人工设定。尚未确定：

- 不同任务中各指标是否应该采用不同权重；
- 系统应该只排序已有候选，还是主动提出新候选；
- 当系统与专家判断冲突时，应提示、解释还是建议回退；
- 如何评价推荐质量，而不把“专家是否接受”简单等同于正确性。

### 5.4 人机交互评价方案还不够成熟

除了完成时间和准确率，还需要衡量：

- 用户是否主动检查多个模式、反例和不确定性；
- 是否理解推荐原因；
- 是否能正确复述结论的适用范围；
- 是否愿意继续探索；
- 是否对 AI 形成了过度信任。

这些指标需要进一步转化为可执行的实验任务和量表。

### 5.5 AI 的可信边界需要提前设计

如果直接让 LLM 读取图表并自由回答，很容易出现无来源数值、过度推断或把相关性解释成因果关系。因此需要先完成证据结构、来源追踪、拒答条件和验证入口，再接入模型。

### 5.6 工程和数据方面的问题

- 原始年度全球数据较大，网络下载耗时，需要继续依赖断点续传和区域裁剪；
- 全部 225 个切片是否都需要下载，应由研究任务决定；
- 当前 Python 环境存在 NumPy/xarray 的二进制兼容警告，虽然测试通过，但后续应固定依赖版本；
- 随着数据增加，年度汇总需要缓存或增量计算，避免每次交互重新扫描全部 NetCDF。

## 六、希望导师提供的帮助

### 6.1 帮助确定主研究场景

希望讨论是继续以 NEX-GDDP 气候投影作为主要案例，还是尽快迁移到黑潮/海气耦合任务。我的倾向是先用 NEX-GDDP 把通用探索推荐框架做完整，再选择一个海洋任务验证迁移性，但需要确认这是否符合预期的研究主线。

### 6.2 帮助明确一个真实、可评价的专家任务

希望能够与领域专家共同确定一到两个具体任务，例如：

> 找出一个在高排放情景下变化明显、但模式一致性仍需核查的区域，并形成可复查结论。

或者在海洋场景中定义一个具有同样“识别 - 解释 - 验证”结构的任务。任务越明确，推荐操作、证据设计和评价指标越容易落地。

### 6.3 帮助校准“值得探索”的评价维度

希望导师帮助判断以下维度是否合理，以及哪些应该成为研究重点：目标相关性、预期信息增益、证据稳定性、新颖性、数据获取成本和计算成本。也希望讨论这些维度是固定加权，还是根据任务阶段动态变化。

### 6.4 帮助联系领域专家或数据合作者

如果后续连接黑潮或海气耦合场景，希望能获得：

- 专家常用的分析流程和判断依据；
- 一到两个真实研究问题；
- 哪些变量、时空尺度和统计证据最重要；
- 对当前原型的早期反馈，而不仅是在完成后进行展示式评价。

### 6.5 帮助审视用户研究设计

我目前考虑比较两个条件：

1. 基础可视分析界面；
2. 带下一步推荐、即时反馈、探索历史和验证提醒的界面。

希望讨论样本量、任务设置、评价指标，以及是否需要把“交互吸引力”和“科学判断质量”拆成两个实验问题。

## 九、一分钟口头总结

这段时间我先把“下一步探索推荐”的想法落到了 SciVis Contest 第三组气候投影数据上，完成了多模式、多情景数据读取、变化与不确定性可视化、验证清单、候选推荐、探索历史和可续传下载流程。现在已有 3 个模式、3 个情景的 9 个锚点切片，代码已推送 GitHub，8 项测试通过。阅读 KuroshioVis 和大模型可视分析综述后，我认为下一步不应只是增加图表或直接接聊天模型，而应先做显式假设、可下钻证据矩阵和可验证的分析闭环，再让 AI 基于结构化证据提供解释。目前最需要讨论的是主研究场景、真实专家任务、“值得探索”的定义以及用户研究评价方法。
