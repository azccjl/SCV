# SciVis Contest 2026 第三组数据：任务分析与针对性建议

更新日期：2026-09-17

## 结论

第三组数据适合被做成一个“下一步探索推荐”问题，而不是一组静态气候图。系统应根据分析者当前的 **变量、时间尺度、空间区域、模式、情景和统计方法**，生成少量候选方向，透明展示每个候选的相关性、信息价值、数据覆盖、模型一致性与计算成本，再由分析者决定是否采用、验证或回退。

建议把研究问题收敛为：

> 可视分析系统能否在多模式、多情景、长时间跨度的气候投影空间中，推荐少量“下一步值得探索”的候选，并通过可追溯的可视证据帮助专家判断这些候选是否科学上有意义？

这与个人想法中的 one-step-ahead exploration 一致，也回应了导师提出的三个核心：**data、task、human perception**。

## 1. 材料带来的约束

### 1.1 NEX-GDDP CMIP6 第三组数据

第三组数据包含历史模拟和 SSP2-4.5、SSP5-8.5 未来投影，具有多模式、日尺度、0.25 度网格和多变量等特征。系统不能把单模式、单年份结果称为长期趋势，也不能把投影称为确定预测。关键证据至少包括：

- 变化幅度：相对历史基准的绝对或相对变化；
- 模式一致性：同向模式比例与跨模式离散范围；
- 情景分叉：SSP2-4.5 与 SSP5-8.5 从何时开始明显不同；
- 数据覆盖：海陆缺测与变量可用性，空白不等于零变化；
- 稳健性：更换基准期、季节、空间范围和模式后，结论是否保留。

### 1.2 KuroshioVis 报告

附件报告不是“多画几张海洋图”，而是围绕明确假设组织一条粗到细的证据链：先定位涡旋事件并对齐成集合，再通过界面复合图、跨界面流场和证据矩阵逐层核查。其最值得迁移的设计有四点：

1. **显式假设优先于自由浏览。** 用户先写出待检验关系，系统再决定所需变量、事件和统计证据。
2. **从个例转向集合证据。** 单个涡旋信号弱，必须跨事件累积均值、一致性与显著性；气候投影同样需要跨模式集合而不是只展示一个模式。
3. **摘要必须能下钻到原始证据。** 证据矩阵单元格可展开散点、回归线和置信区间，避免 AI 或颜色直接替用户下结论。
4. **AI 读取结构化结果，不“看图猜结论”。** 报告中的 Agent 将假设拆成子命题，从预定义证据源取数，再报告支持程度和下一步。这应成为本项目的 AI 边界。

报告也暴露了可借鉴的限制：特征提取受参数影响，当前只覆盖有限时空子集，计算尚未扩展到全分辨率，专家评价只有两人且为演示式评价。因此，本项目要记录参数、支持敏感性检查，并采用任务式用户研究。

### 1.3 大模型赋能可视化与可视分析综述

综述把大模型带来的变化概括为从参数式工具操作走向“人 - Agent - 知识”混合协作。对本项目最重要的不是自动生成图，而是以下三种能力：

- 将自然语言科学目标翻译为可见、可编辑的分析状态；
- 在分析状态和历史基础上提出下一步候选，并解释依据；
- 用结构化证据生成叙述，同时暴露来源、限制和不确定性。

综述同时强调声明式语法仍是自然语言意图与可执行可视化之间的可控中间层，并指出模型评估不等于人类感知，幻觉、偏差、透明度与可靠性仍是核心问题。因此，不应让 LLM 直接生成气候数值或因果解释；它只能组织已经计算和验证的结果。

两份材料共同给出了一条重要边界：AI 可以负责意图解析、任务分解和叙述组织，但数值、统计检验和图表状态必须来自可复算的数据管线。任何自然语言结论都应能返回它引用的模式、情景、年份、变量和统计量。

### 1.4 个人想法与导师建议

TXT 中已经给出一个清楚的起点：分析状态由“变量 + 时间尺度 + 空间区域 + 分析方式”组成，候选价值由目标相关性、视图差异或信息价值、数据访问与计算成本共同决定，系统只推荐少量下一步，而不寻找全局最优路径。

导师建议进一步要求把研究落到人如何完成科学任务：算法和 AI 都要服务于可信、高效的任务完成，并尽可能连接海洋与黑潮场景。这里需要明确一个边界：NEX-GDDP 更适合陆地气候风险投影，当前黑潮区域存在大量缺测；若研究目标转向中尺度海气耦合，应接入比赛海气耦合数据，而不是用第三组数据强行回答海洋动力过程问题。

## 2. Data - Task - Human 的操作化定义

| 维度 | 系统中如何定义 | 当前可测量指标 |
| --- | --- | --- |
| Data | 模式、情景、变量、年份、空间范围、分辨率、缺测和单位 | 文件可用性、有效格点比例、模式数、时间覆盖、加载成本 |
| Task | 定位变化、比较情景、解释模式分歧、验证稳健性、保存工作假设 | 是否找到候选、完成比较所需步骤、是否检查反例与不确定性 |
| Human | 科学目标、当前分析状态、历史路径、接受/拒绝/回退和信心 | 候选采用率、回退率、分支深度、解释理解度、持续探索意愿 |

分析状态应扩展为：

```text
State = variables + model set + scenario + baseline period + target period
      + season + spatial region + statistic + scientific goal
```

候选不应只是一条文本建议，而应包含：操作、推荐理由、预期变化、证据稳定性、计算成本、风险提示和可逆入口。

## 3. Identification - Interpretation - Validation

### Identification：识别

- 从当前数据目录显示模式、情景和年份覆盖，先暴露哪些问题可以回答；
- 用变化幅度、模型一致性、情景差异和数据覆盖生成候选；
- 允许自然语言目标，但必须映射为可见的筛选与指标字段；
- 候选数量控制在 3 个左右，避免将搜索空间原样丢给用户。

### Interpretation：解释

- 情景使用稳定且有语义的颜色，模式使用线型或 small multiples；
- 同时展示集合中位数和四分位范围，不能只画平均线；
- 把“一年内前后半年差异”“跨年变化”“相对历史基准距平”清楚分开；
- AI 摘要只引用当前工作区中已计算的数值，明确“投影不是预测”。

### Validation：验证

- 单击候选可展开原始年度、格点或日尺度数据；
- 一键切换模式、情景、基准期、季节与空间范围，比较结论是否改变；
- 保存每一步状态、推荐分数、用户选择与证据摘要，支持回退和分支；
- 只有完成至少一次替换设置检查后，才能把结论标记为“已验证的工作假设”。

## 4. 三篇指定论文的针对性迁移

### Guided Exploration of Iterative Schedule Modifications

最值得借鉴的是把巨大且无法完全自动优化的空间，转成专家能够逐步判断的局部候选空间。项目中可把“排程修改”替换为“变量/区域/时段/情景/模式/统计方法的下一步修改”。推荐分数必须可拆解，历史必须可回退，系统不能声称找到了唯一正确路径。

### Juicy Interactive Visualization

交互体验应提高继续探索的意愿，但不能用娱乐效果掩盖不确定性。适合加入的反馈包括：筛选后的平滑过渡、候选采用后的明确状态变化、保存证据时的轻量确认、低成本撤销和分支比较。评价不能只记录完成时间，还应测量用户是否继续提出问题、是否主动查看分歧和反例、是否能复述结论为何成立。

### ConceptViz

最适合直接迁移的是 Identification - Interpretation - Validation 流程。AI 的角色依次为：把问题转成查询草案、解释结构化证据、提出验证动作或反例。AI 不负责生成没有来源的数值，也不能把相关关系写成因果机制。

## 5. 从最早两份 PDF 落地的三个模块

### 5.1 假设工作区（优先级 P0）

`KuroshioVis` 的关键不是海洋题材，而是所有视图都围绕显式假设组织。SCV 可以在侧栏增加“研究假设”，并把自然语言拆成可编辑字段：对象、方向、比较组、时间范围和验证条件。例如：

> 在 2035 年，SSP5-8.5 下的区域平均温度相对历史期升高，并且多数模式方向一致。

系统应把它转成 `变量=tas`、`比较=historical vs ssp585`、`目标年=2035`、`证据门槛=同向模式比例`。解析结果必须先由用户确认，之后图表和推荐才围绕该状态更新。这样既吸收了综述提出的自然语言交互，也保留声明式中间状态的可控性。

### 5.2 可下钻证据矩阵（优先级 P0）

借鉴 `KuroshioVis` 的 Evidence Matrix，把“模式 × 情景”或“模式 × 年份”组织为矩阵。单元格颜色表示距平方向，明度或描边表示覆盖率与不确定性；悬停显示样本量、缺测率、相对历史变化和单位，点击后联动到日尺度时间序列与空间网格。它比当前年度折线更适合快速寻找分歧，也能把摘要与原始证据连接起来。

第一版不需要复杂统计模型，只需复用现有 `summarize_records` 结果生成矩阵，并在选择单元格后更新详细切片。第二版再增加 bootstrap 置信区间、跨模式同向比例和异常值提示。

### 5.3 证据绑定的 AI 助手（优先级 P1）

综述强调人 - Agent - 知识协同和“生成 - 评估 - 改进”闭环，`KuroshioVis` 的专家反馈也明确偏好基于底层数据而非通用文本的结论。因此 AI 助手应只读取一个结构化证据包：

```text
hypothesis + active_filters + computed_metrics + data_coverage
+ model_agreement + uncertainty_notes + provenance
```

输出固定为“支持证据、反例/不足、下一项验证动作”三段，并为每句话附上可点击的指标或图表引用。若证据包缺少历史基准、多模式或有效覆盖，助手应明确回答“当前不能判断”，而不是补全结论。所有建议进入探索历史，允许接受、拒绝和回退。

### 5.4 推荐实施顺序

1. 先做证据矩阵，因为它完全基于当前已下载数据，能够立刻提升变化与差异的可见性。
2. 再做假设工作区，让矩阵、筛选器和推荐共享同一份分析状态。
3. 最后接入 AI 助手；先用模板生成证据摘要，完成可追溯机制后再连接大模型。

这三个模块形成一条闭环：`提出假设 -> 定位证据 -> 下钻解释 -> 替换设置验证 -> 修正假设`。它既能成为系统下一阶段的功能主线，也比单纯增加更多图表更容易形成清楚的研究贡献。

## 6. 第二阶段实施范围

### 已实现

- 扫描多文件清单，并按模式、情景、年份选择详细切片；
- 温度与降水单位标准化，显式显示有效格点比例；
- “识别 - 解释 - 验证 - 下一步推荐”四页工作流；
- 历史、SSP2-4.5、SSP5-8.5 与多模式图例规范；
- 跨模式中位数、四分位范围和同向比例；
- 可续传批量下载状态与失败记录；
- 探索历史、候选采用和回退。

### 下一阶段

1. 增加 `tasmax`、`tasmin`、`hurs`，形成热日、暖夜和湿热复合风险主线。
2. 把候选排序从当前启发式分数升级为可配置权重，并记录用户对每次推荐的接受或拒绝理由。
3. 加入基准期和季节敏感性视图，形成真正的验证闭环。
4. 设计两个用户研究条件：基础交互与带即时反馈/探索历史的交互，检验“愿意继续探索”与“是否检查不确定性”。
5. 与海洋专家合作时接入海气耦合数据，将气候投影任务和黑潮中尺度过程任务分开评价，再比较通用推荐框架能否迁移。

## 7. 数据下载策略

不复制 28 TB 全量数据。第二阶段完整计划为 3 个模式、历史 2000-2014、SSP2-4.5 与 SSP5-8.5 的 2030-2044 和 2081-2095，先使用 `tas` 与 `pr`，共 225 个区域年度切片。下载器逐变量下载年度源文件，裁剪并校验区域后立即删除缓存；最终本地切片预计远低于 2 GB。

这里应优先增加科学覆盖，而不是为了达到“几个 GB”而堆文件。只有当核心比较跑通后，再加入 `tasmax`、`tasmin` 和 `hurs`。每次扩展都应在清单中记录来源 URL、变量、模式、情景、年份、经纬度、尺寸、状态和错误。

## 8. 评价方案

建议让参与者完成同一任务：“找出一个在 SSP5-8.5 下变化明显、但模式一致性需要进一步核查的区域，并形成可复查结论。”记录：

- 找到第一个候选所需时间；
- 探索步骤、分支数与回退次数；
- 是否检查多个模式、两个情景、数据覆盖和替代参数；
- 最终结论中的不确定性表述是否正确；
- 主观理解度、信任校准和继续探索意愿。

真正的研究贡献不应是“AI 推荐得更准”，而应是：**透明的一步推荐能否让专家用更少的盲目尝试，形成更完整、可回溯、包含不确定性的证据链。**
